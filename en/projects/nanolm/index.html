NanoLM

A GPT-style transformer built from scratch in PyTorch — BPE tokenizer, training loop, from-scratch LoRA fine-tuning — served as a streaming local chat.

Feature walkthrough

  • GPT from scratch: tokenizer → data → model → train → sample

  • Live generation-parameter controls (temperature · top-k · penalties)
  • Before/after fine-tuning comparison, generated from real checkpoints
  • Streaming FastAPI inference + chat UI

Measured results

  • Pre-training: 28.3M-parameter GPT, 6000 steps in 28 minutes on an 8GB laptop GPU (29–87K tok/s), loss 9.50 → 0.10 (train), best val 5.02; a custom BPE tokenizer (12,000 vocab) round-trips exactly.
  • LoRA fine-tuning: 28 adapters, 1.60% of parameters trainable (0.459M), 442/49 instruction pairs, val loss 4.03 → 0.84 in 3 minutes; before it the model outputs gibberish, after it answers a poisoning question correctly.
  • Held-out evaluation, protocol v2 (44 hand-written questions, 3 seeds, word-boundary matching, polarity enforced): 30.3% hit rate, pooled 95% CI [23.1%, 38.6%].
  • The v1 figure of 38.6% was inflated by substring matching (“cook” credited by “cooking”); the same answers score 31.8% under the corrected rule.
  • The uncomfortable number is the baseline, and it is reported: a pure keyword-lookup table over the fine-tuning answers scores 59.1%, beating the 28M-parameter model by ~29 points.
  • With 133 epochs on 370K tokens (8.7% of a Chinchilla-optimal budget) and a val curve that bottoms at step 1200 then rises, pretraining memorised phrasings and LoRA taught the answer format, not knowledge.
  • A from-scratch KV cache, validated by asserting cached and uncached decoding agree token-for-token, then measured: CPU fp32 77.5 → 205.0 tok/s (2.65x), CUDA fp32 82.3 → 301.1 (3.66x), CUDA bf16 96.2 → 288.1 (3.00x).
  • The same benchmark exposed that v1’s repetition penalty cost 11.8 ms/step in device syncs and made the decoding loop index-out-of-bounds under bf16 — both fixed.
  • True token-level SSE streaming (first token ~0.6 s), inference fully local at zero API cost.
  • CPU and CUDA sampling are now byte-identical across seeds (132/132 answers), which v1 violated — 52.3% on CPU vs 38.6% on CUDA for one checkpoint.
