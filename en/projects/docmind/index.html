Feature walkthrough

  • Structured field extraction with per-field confidence signals
  • Declarative rule engine: duplicate / arithmetic / tax anomalies
  • Interactive knowledge-graph explorer — object filters, node focus, transaction legend
  • Invoice detail drawer: confidence bars, audit evidence, graph connections
  • Audit statistics charts (by rule / by severity)

Measured results

  • 94.1% field-level accuracy (up from 82.5%): 30 synthetic invoices, real qwen-vl-plus API, re-measured after the extractor fix.
  • Per field: date / buyer / seller names 100%, invoice number and tax amount 96.7%, amount incl. tax 93.3%, buyer tax ID 83.3%, seller tax ID 75.9%.
  • Field accuracy only says an invoice was read correctly; whether the audit flagged the right ones is measured separately.
  • Fed labelled field values, the audit engine scores micro P = R = F1 = 1.000 (12/12 anomalies, 0 false positives) across the 7 injected anomaly classes.
  • Read that as detector-agrees-with-generator, not generalisation: the synthetic generator writes the labels and applies exactly the perturbation each rule looks for.
  • The 1.000 does not survive real OCR — fed what the vision model actually returned, micro F1 first dropped to 0.676.
  • After the extractor repair the same measurement gives P 0.733 / R 0.917 / F1 0.815, the run-to-run spread collapsing from 0.16 to zero.
  • Survival, not accuracy, was the highest-value defect: 12.2% of extraction attempts failed outright, every one the same malformed JSON in the model response.
  • A decode-side repair layer took that to 0% (90/90 read; 41 of 90 responses repaired) and batch accuracy from 0.8272 to 0.9411 (+11.4 pp, 3-round mean, range 0.9398–0.9436).
  • The repair’s first version was wrong and re-measuring caught it: it zeroed the failure rate but produced 18 fields where the model reported confidence 1.0 on a value of 0.0.
  • Cause: the model repeats a line-item template as a top-level key after the correct document, and JSON last-wins let the placeholder overwrite a correctly read value — now first-occurrence-wins.
  • Repair recovers framing, never invents values: an internally contradictory payload is rejected outright, and a document with no invoice fields at all still counts as a failure.
  • OCR error runs both ways in one invoice: the model wrote 706.09 for an amount that is really 656.09, which makes the document self-consistent, so the injected arithmetic anomaly goes silent.
  • The same wrong number disagrees with the QR code decoded from the pixels, manufacturing a finding on a document that was not anomalous in that way.
  • The fallback is flagged unverified: the configured secondary model returns 403 in this environment and was never called, and the corrective re-read fired once in 90 documents.
  • Cost and scale moved with the fix: ¥0.3605 → ¥0.3138 per run, 16.7 s → 12.9 s per invoice; the 100k extrapolation goes from ~¥401 / ~148 h / ~12,200 needing review to ~¥349 / ~92 h / 0.
  • 8 audit rules with severity and evidence, incl. QR cross-validation and GB 32100-2015 tax-ID repair.
  • Two failure modes that would have made the audit silently useless are fixed and regression-tested: an all-failed batch no longer reports success, and one crashing rule no longer discards the batch’s findings.
