功能展示

  • 自研轻量多智能体编排（不依赖重型框架）
  • 免费 arXiv API 集成，Crossref 兜底
  • DeepSeek function calling + JSON 任务板
  • 确定性引文核验视图——引文位置与上下文，由代码判定
  • 输出结构化审阅 + 相关工作综述

实测结果

  • 引文核验由代码完成，而不是再问一次模型——对归档的 131 条论断全量重算，26 次“未找到”里有 24 次是核验器自身的问题。
  • 问题出在 PDF 换行连字符与抽取噪声插入的数字；命中率从 102/131（77.9%）到 130/131（99.2%）。
  • 唯一残留的一次是真的不在论文里的引文，所以修复消除了假阴性且没有换来任何假阳性。
  • 把归档报告与机器判定对账，暴露出此前无法察觉的失效模式：17 份报告里 11 份与判定不一致，38 条已被降级的论断仍写作“有据”。
  • 现在报告带由代码写入的核验台账与生成后一致性校验；工具层抓取会逐跳拒绝私网地址（用真实绑定在 127.0.0.1 的服务验证过）。
  • 四智能体流水线比单次长 prompt 强吗？真实调用实测（三臂、各 5 次重复）：它没有买到质量，买到的是可审计性。
  • 14 条贡献清单覆盖度：单次 prompt 14.0（区间 14–14）、流水线 13.4（13–14）——区间重叠，流水线 5 次里有 2 次满分；两者事实错误均为 0。
  • 要撤回一个结论：三次重复时覆盖度看似分离（14/14 对 13/14），我那时就是这么写的；五次重复后区间重叠，能站住的只有“本样本内未测得质量差异”。
  • 用同一批已存报告重评还显示：重叠在 n=3 时其实就已存在——那个“分离”是三样本的噪声。
  • 流水线独有的产出：每条论断都带代码可定位的引文（机器层 9.8/9.8 条，100%），报告含由代码而不是模型写入的核验台账（5/5 轮）。
  • 单次 prompt 那一臂没有 claim 产物，引文无从核验；一个 fixture 显示：Reader 编造引文时流水线把该条改写成 [unverified]，而关闭核验的一臂照样以 [supported] 交付。
  • 成本是唯一跨样本量稳定的列：每次审阅贵 4.31 倍（¥0.1138 对 ¥0.0264），按调用逐次记账——9 次 LLM 调用对 1 次，多付约 4.3 倍换来可被 LLM 之外检验的论断。
  • 波动也如实说：流水线逐条的“可定位引文率”并不稳定（各次运行 0.0–0.182），跑一次的结果不该被当作稳定值。
  • 这类实验最容易撒谎的地方：第一版评分器给出每臂 1.7–2.3 个事实错误，逐条核对后全是评分器自己的 bug。
  • 它把一句话两两比对（“Group E: A=44.2%, B=54.6%, C=53.8%, E=68.8%”），凭空造出 5 个张冠李戴；用同一批已存报告零新增 API 重新评分，各臂事实错误全部为 0。
  • 另一次产物完整性审计发现：原 9 个 run 目录里有 4 个在测量之后被覆写过，所以已发布的 n=3 数字从 git 原样保留，两种读法连同时间戳并列展示。
